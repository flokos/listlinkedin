# 09: API design

V2's HTTP API lives under **`/api/v2/`** and is built from DRF **ViewSets**
([ADR-010](adr/ADR-010-viewsets-and-api-v2.md)). V1's `/api/v1/` stays during the transition
(see [v1 compatibility](#api-v1-during-the-transition)). The OpenAPI 3 schema is generated by
drf-spectacular at `/api/schema/?version=v2`, with Swagger at `/api/docs/` (V1 setup, extended
per version).

## Conventions

| Topic | Rule |
|---|---|
| Format | JSON in and out (V1 parsers and renderers). `multipart/form-data` only on the upload endpoints |
| Identifiers | Lists by `public_code` (`{code}`), groups by `code`, links by UUID, revisions by `number`, members by user id. UUID `id`s are returned but are never needed in URLs except for links |
| Authentication | Django session cookie (`sessionid`, `HttpOnly`, `Secure` in production, `SameSite=Lax`) with **CSRF** on unsafe methods (`X-CSRFToken` header from the `csrftoken` cookie [R8]). Legacy lists also accept `Authorization: Bearer <owner token>`, which needs no CSRF because it isn't ambient |
| Authorization | [12-AUTHORIZATION.md](12-AUTHORIZATION.md). Not viewable → 404. Viewable but forbidden → 403. Account required → 401 with `WWW-Authenticate: Session` (`Bearer` on endpoints that also accept legacy owner tokens) |
| Pagination | `PageNumberPagination` shape `{count, next, previous, results}` (V1-compatible). Default 20, max 100. A list's links default to 100 per page, which is the whole list |
| Ordering and filtering | `?ordering=` on collections where documented. `?q=` and `?tags=a,b` on the directory |
| Versioning | URL path. `/api/v1/` is frozen and deprecated (`Deprecation` and `Sunset` headers once V2 ships). Breaking changes inside v2 are forbidden after release; additive changes are fine |
| Concurrency | List representations carry `ETag: "r{head_revision}"`. Content writes accept `If-Match` (412 on mismatch). **Restore and sync require it** (428 if missing) |
| Idempotency | `Idempotency-Key: <uuid>` is accepted on create list, create link, fork and branch (stored as `creation_key`). It is **required** on sync apply ([08](08-SYNCHRONIZATION-SPEC.md#identifiers-fingerprints-and-idempotency)) |
| Rate limits | DRF scoped throttles keyed by user id when signed in and by client IP otherwise, stored in the PostgreSQL DatabaseCache with V1's advisory-lock fix. Reads aren't throttled except directory search |
| Errors | DRF's shapes (V1-compatible: `{"detail": …}` or `{field: [messages]}`) plus a stable machine `code` |

### Error format

```json
{"detail": "The source list changed while you were reviewing.", "code": "stale_preview", "fingerprint": "…"}
{"destination_url": ["This URL is already in the list."], "code": "invalid"}
```

Domain code raises framework-free exceptions that subclass the categories in
`apps/common/errors.py` (for example `versioning.domain.errors.StalePreview(Conflict)`).
`config/exceptions.py`, the DRF `EXCEPTION_HANDLER`, maps them to a status through the class
hierarchy and adds `code` (plus any extra fields, such as `fingerprint`) to every error body
under `/api/v2/`. V1 bodies keep their exact V1 shape. Services written in V1 style that raise
DRF exceptions stay valid until touched. Infrastructure errors (DB timeouts, lock timeouts)
map to 503 `temporarily_unavailable` with `Retry-After`, never to raw 500 text.

| Domain error | HTTP | `code` |
|---|---|---|
| `NotVisible` | 404 | `not_found` |
| `Forbidden` | 403 | `permission_denied` |
| `AuthenticationRequired` | 401 | `not_authenticated` |
| `Expired` | 410 | `gone` |
| `RevisionMismatch` | 412 | `revision_mismatch` |
| `PreconditionRequired` | 428 | `precondition_required` |
| `StalePreview`, `ParentUnavailable`, `NotABranch`, `Conflict` | 409 | as named |
| `InvalidDecisions`, `LinkLimit`, `DuplicateUrl`, `IdempotencyKeyReused`, validation | 422 or 400 | as named (field errors stay 400, as in V1) |
| `RateLimited` | 429 | `throttled` + `Retry-After` |

## URLs and slugs

- The canonical list URL is `/l/{code}/{slug}`, where the slug is cosmetic and ignored when
  resolving. `/l/{code}` alone keeps working forever (V1 links). The SPA rewrites the address to
  the current slug. The slug is regenerated from the title unless the owner edits it.
- Reserved second segments: `manage` (the V1 edit link `/l/{code}/manage#t=`), `history`,
  `sync`, `settings`. Slugify appends `-list` if a title would produce one of these.
- Group URL: `/g/{code}/{slug}`. Group context for a list: `/g/{code}/l/{listCode}`.
- Short link redirect: `/r/{code}` (V1, unchanged except for the visibility rule).

## Session and account

Authentication flows use **django-allauth headless, browser client**: `/_allauth/browser/v1/…`
[R6]. The SPA uses `POST auth/login`, `POST auth/signup`, `DELETE auth/session` (sign out),
`POST auth/password/request`, `GET`/`POST auth/password/reset` (GET checks a key sent as
`X-Password-Reset-Key`), `POST auth/email/verify`, `PUT account/email` (resend verification;
**403 means nothing was sent**, because one went out recently or the address is verified) and
`POST account/password/change`. **A 401 from sign-out, password reset or verify-while-signed-out
means the step succeeded and left the browser signed out.** Errors are
`{status, errors: [{message, code, param}]}`. The project adds:

| Method | Path | Notes |
|---|---|---|
| GET | `/api/v2/session/` | Sets the CSRF cookie. Returns `{user: {id, email, display_name, email_verified} \| null}` |
| GET | `/api/v2/me/` | The signed-in user (401 when signed out) |
| PATCH | `/api/v2/me/` | `display_name` (≤80 characters, trimmed). `email` is read-only here; changing it goes through allauth's verified flow |
| DELETE | `/api/v2/me/` | Account deletion. Requires `{"confirm": "<email>"}`, and deletes owned lists and groups first ([04](04-DOMAIN-MODEL.md#ownership-rules)) |

## Lists

| Method | Path | Who | Notes |
|---|---|---|---|
| GET | `/api/v2/lists/` | signed in | Lists the user owns or is a member of. `?role=owner\|editor\|viewer`, `?q=`, `?ordering=-updated_at\|title` |
| POST | `/api/v2/lists/` | signed in | `{title, description?, visibility?, expires_at?}` → 201 + revision 1. `Idempotency-Key` optional |
| GET | `/api/v2/lists/{code}/` | can view | Detail (below). `ETag` |
| PATCH | `/api/v2/lists/{code}/` | editor (content) / owner (settings) | Content fields write a revision; settings don't |
| DELETE | `/api/v2/lists/{code}/` | owner, legacy token | 204. Hard delete |
| POST | `/api/v2/lists/{code}/claim/` | signed in + `Authorization: Bearer <token>` | Makes the caller owner and retires the token (atomic). 200 → detail |
| POST | `/api/v2/lists/{code}/rotate-token/` | legacy token | `{owner_token}` (V1 behaviour) |
| PUT, DELETE | `/api/v2/lists/{code}/image/` | editor | multipart `file` ≤2 MB → re-encoded ([ADR-012](adr/ADR-012-media-and-images.md)) |
| GET, POST | `/api/v2/lists/{code}/members/` | owner (editors may read; viewers 403). Session only | POST `{email, role}` with role `editor` or `viewer` → 201. The owner needs a verified email (403 `email_unverified`), and so does the added account: unknown and unverified addresses get the same 400 on `email`. Rate limit `member_add` |
| PATCH, DELETE | `/api/v2/lists/{code}/members/{user_id}/` | owner; members can DELETE themselves (leave) | PATCH `{role}` → 200. DELETE → 204. The owner can't leave (403) |

A member is `{user_id, display_name, email_hint, role, added_at, is_you}`. `email_hint`
(`b…@example.com`) tells people apart without showing the address ([12](12-AUTHORIZATION.md#leak-analysis)).


List detail:

```json
{
  "id": "550e8400-…", "code": "X7pKm2Qv8Nw4Rs6A", "slug": "dev-tools",
  "url": "https://go.example.com/l/X7pKm2Qv8Nw4Rs6A/dev-tools",
  "title": "Dev tools", "description": "", "image_url": null,
  "visibility": "unlisted", "allow_fork": true, "allow_branch": false, "tags": ["dev"],
  "owner": {"display_name": "Theo"}, "legacy": false,
  "created_at": "…", "updated_at": "…", "expires_at": null,
  "head_revision": 14, "link_count": 12,
  "my_role": "owner", "permissions": ["view", "view_history", "edit", "settings", "view_members", "members", "delete", "fork", "branch"],
  "origin": {"kind": "branch", "parent": {"code": "…", "title": "Team tools"}, "sync": {"state": "updates_available", "behind": true}}
}
```

`permissions` comes from the policy, so the UI never re-derives rules. `owner` is present
only when the viewer may see it ([12](12-AUTHORIZATION.md#leak-analysis)). `origin` is
null for ordinary lists. `parent` is null when the viewer can't view the parent.

## Links

| Method | Path | Who | Notes |
|---|---|---|---|
| GET | `/api/v2/lists/{code}/links/` | can view | Live links by `position` (page size 100) |
| POST | `/api/v2/lists/{code}/links/` | editor, legacy | `{destination_url, title?, description?, position?}` → appended unless `position` is given. Creates the short URL and enqueues metadata |
| PATCH | `/api/v2/lists/{code}/links/{id}/` | editor, legacy | `title`, `description`, `destination_url`. The `id` and short URL are preserved (K1) |
| DELETE | `/api/v2/lists/{code}/links/{id}/` | editor, legacy | 204. Tombstone |
| POST | `/api/v2/lists/{code}/reorder/` | editor, legacy | **Move** semantics: `{"link": "<uuid>", "to_index": 3}` (clamped, 0-based among live links). Moving to the same index is a no-op. Concurrent moves serialize under the lock, so none is lost |
| POST | `/api/v2/lists/{code}/links/{id}/move-to-list/` | editor of both lists | `{"list": "<target code>"}`. Copy + tombstone (K4). The new link gets a new short URL |
| PUT, DELETE | `/api/v2/lists/{code}/links/{id}/icon/` | editor (account) | multipart icon ≤2 MB, re-encoded to 128×128. Versioned |
| POST | `/api/v2/lists/{code}/links/{id}/refresh-metadata/` | editor | 202. At most once per hour per link |

Since task 1.4 the links list, create, update and delete endpoints exist with the V1 link
representation, newest first, and a hard delete. Task 2.1 adds `position`, `description` and
tombstones; the rest of the table follows in phase 2 and 7.

Link representation (V1 fields kept, new fields added):

```json
{
  "id": "8f6d…", "destination_url": "https://example.com/article", "short_url": "https://go.example.com/r/Ab3Kp7Nq2Wz8Lm5R",
  "title": "Interesting Article", "description": null, "icon_url": null, "position": 0,
  "display": {"title": "Interesting Article", "description": "From the page…", "icon_url": "/media/meta/2b9e….webp", "site_name": "Example"},
  "metadata_status": "ready", "source_link_id": null, "created_at": "…", "updated_at": "…"
}
```

`display` applies the precedence rule user > fetched > fallback, so clients don't reimplement
it. `metadata_status` is one of `pending`, `ready`, `unavailable` or `disabled`.

## Revisions and restore

| Method | Path | Who | Notes |
|---|---|---|---|
| GET | `/api/v2/lists/{code}/revisions/` | editor, owner, legacy | Newest first: `{number, kind, created_at, author: {display_name} \| "edit link" \| null, summary, restored_from}` |
| GET | `/api/v2/lists/{code}/revisions/{number}/` | same | `{…summary fields, snapshot, diff_from_previous}` (snapshot rendered with link labels) |
| POST | `/api/v2/lists/{code}/restore/` | editor, legacy | `{"revision": N}`. `If-Match` **required**. 200 `{revision: new head, changed}` |

| Method | Path | Who | Notes |
|---|---|---|---|
| POST | `/api/v2/lists/{code}/fork/` | see [12](12-AUTHORIZATION.md#list-permission-matrix) | `{title?}` → 201 new list. `Idempotency-Key` optional |
| POST | `/api/v2/lists/{code}/branches/` | same, with `allow_branch` | `{title?}` → 201 new child |

| GET | `/api/v2/lists/{code}/sync-status/` | editor of child | `{state, parent_revision, base_revision, counts?}` |

| Method | Path | Notes |

| GET | `/api/v2/directory/lists/` | `public` only. `?q=` (websearch syntax on title and description [R11]), `?tags=a,b` (AND), `?ordering=-updated_at\|title\|-relevance`. Paginated. Throttled per IP |

## Uploads

Upload endpoints are the only ones above the 16 KB request limit. The request-size middleware
gets a per-route allowance (2 MB), and nginx gets a matching `location` with
`client_max_body_size 3m`. Everything else keeps the V1 limits.

## Concurrency preconditions

- `ETag: "r{head_revision}"` is sent on list detail and links collections.
- `If-Match` is **required** on restore and sync. It is optional on PATCH/POST/DELETE of
  content: the UI sends it when it shows a form based on a loaded state, and a 412 makes the UI
  reload and re-show the form with the user's input kept.
- Reorder (move) needs no precondition: a move is always applied to the current order.

## API v1 during the transition

| V1 endpoint | V2 behaviour |
|---|---|
| `POST /api/v1/lists/` | **410** `{"detail": "Creating lists now requires an account."}` (v1 bodies carry no `code`), since task 1.4. The `LEGACY_LIST_CREATION=on` switch keeps it working for tests and e2e seeding only ([ADR-011](adr/ADR-011-accounts-required-legacy-lists.md)) |
| `GET /api/v1/lists/{code}/`, `…/links/` | Unchanged representation for `unlisted` and `public` lists. `private` → 404 |
| `PATCH/DELETE …`, `…/links/…`, `rotate-token` | Legacy token on unclaimed lists only (same services as v2). Claimed → 403 |
| `/l/{code}` on Django | 302 to the v1 API representation (unchanged). Behind nginx the SPA handles it |

`/api/v1/` is removed in the first release after the last legacy list has expired: at most
30 days after V2 launch, plus the cleanup lag (roadmap task 9.6).

## OpenAPI

- One schema per version (`SPECTACULAR_SETTINGS` + `?version=`). The cookie/CSRF scheme and
  the legacy `OwnerToken` bearer scheme are both declared. Public reads are marked
  unauthenticated, as V1 tests already assert.
- The frontend's TypeScript types are generated from the v2 schema with `openapi-typescript`
  ([10](10-FRONTEND-ARCHITECTURE.md#api-integration)). CI fails if the generated file is stale.
